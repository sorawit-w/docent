Report a bug and get a fix

A bug report goes from the reporter to the maintainers and comes back once. It ends in a new version, such as 2.4.1. This guide shows the path and the four steps.

Guide
  • 4 minutes to read
  • Updated 15 November 2026
  • Owner: Maintainers

The short version

A reporter finds a problem and writes a bug report. The maintainers check each new report. This first check is called triage, and it gives the report a label such as confirmed.

The maintainers often need the exact steps that show the bug. You send the steps, and they write the fix. The triage result tells you what happens next.

Note A report asks for a fix. It does not promise a date. The maintainers decide the order of the work.

Walk through a bug report

Follow the dot. Each step names one arrow in the figure.

  1. You file the report.

    The report says what you did, what you expected, and what happened.

  2. The maintainers ask for steps.

    They check the report first. They can fix only a bug that they can see.

  3. You send the steps.

    Write a short, exact list. Add the version, such as 2.4.0.

  4. The maintainers release the fix.

    They test the fix. Then it goes into a new version.

The parts

Five parts take part in a bug report. Two belong to the reporter, and three belong to the maintainers.

Triage results

The first check ends in one of three ways.

ResultWhat it meansWhat you doState
ConfirmedThe maintainers can see the bug.Wait for the fix, then install the new version.Continue
Needs stepsThe maintainers cannot see the bug yet.Send the steps, then wait.Answer, then continue
Not a bugThe program works as designed.Read the reply. Do not file the report again.Stop
Warning

A report with no steps often waits a long time. Send the steps with the first report when you can.

Commands

Run these in a terminal before you write the report.

# 1. Note the version
app --version

# 2. Repeat the failing step and keep the log
app export --verbose > bug.log

# 3. Check that the log holds no password
grep -i password bug.log
Why the maintainers ask for steps

A fix needs a test. The test repeats your steps, and it fails before the fix. After the fix, the same test passes. The test stays, so the same bug cannot come back unseen.
